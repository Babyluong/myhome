# Planning material work

Babybun owns plans and decision records; Amri owns user-facing approval, dispatch and acceptance. This skill never authorizes Babybun to implement or send another specialist work.

1. Establish the deliverable, current contracts, approved scope, side effects and meaningful unresolved decisions from the task and relevant source.
2. Compare alternatives only when a real choice exists. Record a recommended approach and why it fits the installed stack and user intent.
3. Produce owner-specific slices with exact paths, inputs/dependencies, testable criteria, checks and report destination. Avoid fixed file-count or line-count thresholds.
4. Send the plan to Amri. For substantial new scope, Amri obtains approval of a concrete reviewable plan before implementation. Existing approval is sufficient for unchanged approved slices; do not ask again by default.
5. During continuation, record meaningful scope changes, decisions and next steps in assigned records. Refer consequential changes to Amri; do not silently broaden authorization.

Routine reversible fixes with settled behavior can use a short task card. Required planning, security and verification are determined by consequences, not an arbitrary size rule.
