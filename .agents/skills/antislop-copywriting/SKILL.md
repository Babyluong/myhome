# Clear product copy

This is self-contained H.O.M.E. guidance. No external antislop core or numbered rule set is required.

- State the concrete action or fact early, in familiar language. Use connected sentences and the structure the reader needs.
- Keep the user's voice and explicit choices. Edit unnecessary ceremony, repeated slogans and vague claims without imposing a universal punctuation or tone ban.
- Never invent statistics, clinical facts, customers, quotes, citations or product features. Use verified source detail; ask only when essential information is missing.
- Label buttons by what they do. Explain field requirements and errors where they help the user complete the task. Keep implementation details out of ordinary product flows.
- Distinguish pending, success, empty and failure messages honestly. Do not describe a skipped check as passed or claim flawless, secure or production-ready behavior without the required evidence.
- Use headings, lists and emphasis when they improve scanning, rather than mechanically repeating formatting patterns.
- Review the completed copy in the actual page context for fit, readability, localization and accessible names.

For changes to sensitive operational wording or data contracts, send the decision to Amri and the responsible specialist. Follow the active design system and approved page brief.
